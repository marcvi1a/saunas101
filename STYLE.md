# Saunas 101 · style

The page follows saunaslava.com.br: EB Garamond for headings, Manrope for text, the cream background, a content column that starts where the site's header logo starts (1100 px wide, centred: half the space beyond 1200 px plus 50 px, measured on the live site; 20 px gutters under 990 px).

## Writing

1. Numbers are always digits: 2 bathers, 3 changes an hour, 20 cm, 90 °C. The only number written as a word is one. Fractions stay words: half, a third, a quarter.
2. Units as symbols, never spelled out: 20 cm, 90 °C, 6 l/s, 1 kW per m³. A figure never parts from its unit at a line break: the build puts a narrow no-break space (U+202F) between them in every page, and `site.js` does the same in every text it writes or converts, so the sources can use a plain space. A spelled-out metre does not convert and reads wrong in Imperial. Metric is the source; the Imperial toggle converts every figure on the page, so never hand-write an imperial value.
3. Short sentences. No exclamation marks. No "the user". No brand names in the rules, and no mention of Lava anywhere: the page reads as an objective guide.
4. Rule titles name the rule in words and carry no figures and no final full stop (Low ceiling, Warm feet); the figures go in the description, which runs 2 lines on desktop: between 140 and 160 characters, checked at build. Rules are numbered in the title's own type and the numbers run on across pages (construction 1 to 9, heater 10 on): the build writes them, the sources carry none.
5. Rules are about building. Upkeep (restacking stones, cleaning) is not a rule.
6. Links inside text look as on saunaslava.com.br: no underline, the muted brown (#7C6A64), a shade darker on hover.

## Pages and addresses

Three pages, one per section, each with its own title, description, canonical address and place in `sitemap.xml`:

1. `/construction` is Construction (`construction.html`). The root `/` (`index.html`) serves the same page and names `/construction` as its canonical address, so the home is never empty and search engines count one page.
2. `/heater` (`heater.html`; GitHub Pages serves the file at the extensionless address).
3. `/ventilation` (`ventilation.html`).

The path names the page; the fragment names the view inside it. A rule's anchor is its id: `/construction#ceiling`, `/heater#glass`. A click on a rule puts its anchor in the address. The calculator's sizes live in the fragment of the heater page, in metres: `/heater#2.1x2.1x2.1` (width × depth × height) and `/heater#2.1x2.1x2.1+1` with 1 m² of glass; the calculator rewrites it on every input, and the Share control under it copies one line and that link (the system share sheet on touch devices, "Link copied" for 2 s elsewhere), the control copied from saunaslava.com.br. The same control sits under the construction pictures and under the ventilation drawing; `data-share` names the payload. The lines are fixed wording, with no figure next to the 101: "Saunas 101: Construction rules for building a proper Finnish sauna." (the button's `data-text`), "Saunas 101: Electric heater calculator 10 kW." and "Saunas 101: Ventilation diagram with all variables explained, score 100.", each followed by the link that reopens the view. The lab's layout lives in the fragment of the ventilation page as 7 words in switch order, the switches' own words in lowercase: inlet (above, middle, low, floor), exhaust (lower, upper), fan (exhaust, none), duct (none, long, short, inlet), heater (open, closed, wall), inlet angle (straight, 45), drying vent (closed, open). The landing state, Mechanical ventilation, is `/ventilation#above-lower-exhaust-none-open-straight-closed`; Absolute best `#above-lower-exhaust-long-open-straight-closed`; Gravity `#low-upper-none-none-open-straight-closed`. With no ventilation only the heater is left: `#no-open`, `#no-closed`, `#no-wall`. The lab rewrites it on every change, so the address always reopens the same view; a fragment that does not parse is ignored and the landing state shows. No older address grammar is kept: the site is new. Never a query string: a query would make every layout a crawlable address. No units in any address: units are the reader's preference, kept in localStorage. The one exception is Imperial: while it is on, the address carries `?units=imperial` (set by the toggle and on load from the stored preference), so a copied address or a Share line reopens the same view for the recipient; Metric, the default, carries nothing. The page honours the parameter without storing it, and the canonical tag keeps search engines on the plain address.

## Columns

Every page is two columns from 1200 px up: the text column at the left (`minmax(0,1fr)`, 582 px inside the 1100 px content column) and the tool column at the right (`--col-tool`, 470 px, 43 % of the content column), 48 px apart. The text column is wider than the paragraphs' 64ch (about 530 px), so rule descriptions keep their 2 lines. Left holds everything that is read: rules, the 4 named layouts, the note. Right holds only a tool: the pictures, the calculator, the ventilation card with its score, drawing and switches. Under 1200 px the pages are one column.

## Heater calculator

The Heater page carries a small calculator, a white card to the right of the rules from 1200 px up and after the rules below that (never between rules), styled as a tool (eyebrow title, plain labels) so it never reads as a rule, and sticky under the masthead on wide screens until the rules end (the masthead height is measured into `--masthead`): width, depth, height and the area of glass give the room volume (plus 0.6 m³ per m² of glass) and the heater size, 0.8 kW per m³ rounded to the nearest kilowatt, on two lines: the volume, then "It needs an electric heater of about N kW." It keeps its figures in metres and renders them itself in the reader's units, so its block is marked `data-nounits` and the text converter skips it.

## Construction pictures

The first 3 rules are drawn: three white cards at the right of the rules (sticky like the calculator, after the rules under 1200 px), each an inline SVG in the lab's own style: wood interior, black outline, the lab's benches and heater block, the lab's white seated figure (`#bather`, defined once in the first picture and reused with `use`), a red ✗ over each wrong room and a green ✓ over the right one, a mono label under each room. Rooms are to scale within a picture (40 px per metre in the first, 48 in the second, 30 in the third); the hot layer is the top 60 cm of the room. Benches keep their distance from the heater in every room: the lower bench at least 25 cm, the upper at least 40 cm (the too-big room has more), and the one-level bench is exactly as long as the lower bench of the multiple-levels room. Sizes and figures are built from `src/construction.html`'s markup only; no image files.

## Ventilation page

The löyly rule opens the page (it is the reason ventilation matters); the 4 named layouts and one muted note (how the score is built, then the airflow model: 10 px type for the curious, not a part of the page proper, 72 px of air above it) follow it in the text column, one column wide. The layouts, under the eyebrow "Most common layouts", unnumbered (No ventilation; Gravity ventilation: inlet at the bottom, exhaust under the upper bench, no fan, no duct; Mechanical ventilation: inlet above, exhaust under the lower bench, exhaust fan, no duct; Absolute best: the layout with the top score; among layouts tied there, the one that keeps the most points if its fan stops (the score itself never counts a stopped fan); all with the open heater, the straight inlet and the drying vent closed) are buttons that set every switch, each with the fixed score the model gives it and a bar; the rows sit in a grid of 2 by 2, their names in the rules' 21 px serif, no fill, the rose hairline and muted text when not selected (option A of the rows board: the switch track's neutral grey sat cold on the page), white with ink text when selected (never an ink border), 16 px of padding, the score and the bar always in their colours. Nothing in the text column is boxed; the white cards belong to the tool column, so the layouts and the note stand plain on the page. There is no verdict text: the score and the drawing carry the explanation. No score is set by hand anywhere: `model/` (the airflow network, the room's temperature profile and the feet, breathing at the upper bather's mouth, the score) runs in `build.js` over every switch state, its physical invariants must hold or the build stops, and the scores, on a scale from a sealed room with the same heater (0, breathing's zero) to the model's best state (100), go into the generated `scores.js` with `BEST_STATE`, which the Absolute best layout follows. An open drying vent can only lower a score: a layout with the vent open scores the lower of its own physics and the same layout with the vent shut, because the vent is for after the session (rule 16); the drawing still shows what the open vent does. The score is breathing × löyly × heat. Heat is the share of the room's heat, 90 °C at the thermostat over 25 °C outside, that the 2 bathers sit in, averaged from ankles to mouth: a layout that ventilates by cooling the benches cannot score high, because a cold room is not a sauna. The ankle draught is not scored: at sauna heat it moved a score by 1 point at most. The note under the layouts says this in 5 short paragraphs (the score, breathing, löyly, heat, the air), about 95 words. The page states the model's settings in the note: a well-fitted door with 2 mm gaps, the air judged once it has settled, the fan scored running. `model/README.md` and `model/docs/` hold the derivations and the sources. The drawing follows the same model: nothing in it is drawn by hand per layout. For every state the build also writes the model's air into `scores.js` (each opening's flow and direction, where each stream of outdoor air goes first: into the heater, along the floor or to the benches, the part an outlet drains before it reaches the benches, the outlets, the heater's plume, the cold floor layer, how stale the air is), and `lab.js` builds the moving dots from it: one dot per 1.2 l/s, faster when more air moves, blue while the air is cold, turning red where the model heats it, grey stale-air dots in proportion to the CO₂ at the mouth. The labels (now leaks hot air out, now lets cold air in, almost no flow) come from the same flows; the drying vent is labelled with its name only. The dots keep clear of the walls, the floor and the ceiling except where they pass through an opening. The door's 2 mm gaps stay in the model and the score but are never drawn: no vents, no labels, no dots through them, and air the model sends out through them is drawn leaving through the designed outlets. The tool column holds one white card, sticky under the masthead until the left column ends (plain on screens under 780 px tall, where it would not fit): a score line starting at the room's left wall, its parts on one baseline; the drawing; a line under it with the legend at the left wall and the pause icon at the right wall, 8 px of margin under that line (a legend on the score line would wrap to 2 rows whenever the third entry, the stagnant zone, shows); then the 8 switches, one row each, no divider, the small uppercase title (10 px) in a column that starts at the room's left wall and the segmented control (10 px) beside it (in this order: Ventilation, Inlet, Exhaust, Fan, Duct, Heater, Inlet angle, Drying vent; option B of the card board), all one colour, the one-line job as the title's tooltip; an option that cannot apply in the current state (the inlet duct with the floor inlet) is disabled and shown at the same 45 % as a whole switch that cannot apply (the inlet angle with the floor inlet), and a click on the drawing skips it; options name what is built and never On / Off, which reads as a fault (Fan: Exhaust or None; Duct: None, Long, Short, Inlet; Heater: Open, Closed, Wall, kept as the most intuitive); small pills (3 px above and below the word, 2 px of track, 3 px between the options, 5 px between the rows) so all 8 rows fit under the drawing on a laptop viewport of about 816 px. The HEATER label sits inside the drawing, over the stones, so the drawing carries no band under the floor. The exhaust grille's top edge sits 5 cm under the underside of whichever bench it is under, the lower bench at 45 cm or the upper at 90 cm, so the two exhaust positions read the same. Every drawn element that stands for a switch (inlet, exhaust, fan, duct, heater, drying vent) is live: hovering it draws a thin cedar frame round the element's area (a glow filter showed the white masks that hide the duct lines behind the wall openings, so the frame is the hit area itself) and lights its switch row (title in cedar and bold, a cedar line round the control; the title column is fixed at 90 px so the bold never moves the controls), hovering a switch row lights the row the same way and its element in return, and the light survives the redraw a click causes, and a click on the element moves that switch to its next option, wrapping round. Each live element carries an invisible hit area over the drawn thing itself, its words left out, with 6 units of padding (never under 24 square) and kept 2 units inside the drawing's top and sides; the drawing overflows visibly, so the floor inlet's frame runs whole below the floor, over the legend line. Under 1200 px the order is rule, card, layouts, note; the masthead scrolls away and only the tabs stay sticky (14 px of air above them, 22 px under the subtitle, 36 px in all as on wide screens). Under 560 px the card splits: the score line and the drawing stay under the tabs while the switches scroll beneath them, so a phone can flip a switch and watch the air at once; there the switches are a grid of 2 columns, the 4-way pills (Inlet: Above, Middle, Low, Floor; Duct) fold into 2 rows of 2, Exhaust stacks its 2 options, and the buttons tighten to 7 px of side padding, so the widest switch (Heater, 3 options) fits half of a 360 px screen. The right column itself never sticks under 1200 px (a sticky column in the single-column flow slides over the layouts); on phones each switch takes one cell of the grid (the desktop rows span the full width, so the phone rule resets that), the titles align to the top of their row, and the 12 px between the tabs and the pinned card is painted with the page background so nothing scrolling beneath shows through. The Duct options read None, Long, Short, Inlet.

## Code

1. Content lives in `src/`: `layout.html` is the document (head, masthead, tabs, footer slot, scripts), `construction.html`, `heater.html` and `ventilation.html` are the page bodies, `footer.html` the shared footer, `404.html` the not-found page. `build.js` holds the page table (titles, descriptions, scripts) and numbers the rules, writes the pages and the sitemap; it fails the build on a rule that breaks the writing rules, a duplicate id or an inline style.
2. All CSS lives in `styles.css`; `site.js` runs on every page (old addresses, units, calculator, masthead, footer, rule anchors) and `lab.js` only on the ventilation page. No inline `style` attributes; the only style set from script is data (a bar's width, the masthead height).
3. Run `node build.js` before every push and commit the built pages with the sources. The script links carry a hash of the file's content as `?v=`, so a changed file is fetched fresh past GitHub Pages' 10-minute cache and an unchanged one stays cached.
4. Paths in the pages are absolute (`/styles.css`, `/assets/…`), so the folder must be served over HTTP to be viewed locally.
5. Line endings are LF (`.gitattributes`). No dependencies.
